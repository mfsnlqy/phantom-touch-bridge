# 直接开始试

这份文档适合你：

- 已经大概判断自己的设备在支持范围内
- 或者不想继续看判断过程，只想先直接试试

你的目标不用太复杂。先做到这一点就够了：

- 把桥接层跑起来
- 试一次 `Intiface`
- 或者在有一些把握时，再试试 `custom`
- 看看它是不是已经能正常启动

## 开始前你需要有什么

至少准备好这些：

- 一台 Windows 电脑
- 已经从 GitHub 下载好的 `phantom-touch-bridge`
- 如果要试 `Intiface`，先装好并打开 `Intiface Central`
- 如果要试 `custom`，这台 Windows 电脑本身需要能用蓝牙；如果电脑没有蓝牙，需要额外的蓝牙适配器
- 如果要试 `custom`，你最好知道自己设备名称里比较好认的一部分关键词

## 如果你只是想使用，怎么从 GitHub 下载

如果你只是想直接使用，不需要自己改代码，也不需要安装 Python。

更适合你的下载方式通常是：

1. 打开 `phantom-touch-bridge` 的 GitHub 仓库页面
2. 点进右侧或上方的 `Releases`
3. 下载最新发布里的 Windows 压缩包
4. 把压缩包解压到一个你容易找到的位置

解压后，你要找的是一个里面带这些文件的目录：

- `start-server.bat`
- `phantom-touch-bridge.exe`
- `phantom_touch_bridge.example.toml`

后面这份文档里说的“打开目录”，就是打开这个目录。

如果你看到的是 GitHub 自动生成的 `Source code (zip)`，那通常不是给普通使用准备的。  
只想使用时，更推荐下载发布页里的 Windows 压缩包。

## 最短开始方式

1. 打开刚刚解压出来、里面有 `start-server.bat` 的那个目录
2. 双击 `start-server.bat`
3. 菜单里选择你想走的路线
4. 启动后用浏览器打开 `http://127.0.0.1:8765/healthz`

如果浏览器里能看到返回内容，通常就说明桥接层已经成功跑起来了。

## 如果你想先试 `Intiface`

这是当前最推荐、最省心的路线。

### 你怎么做

1. 先打开 `Intiface Central`
2. 确认它已经在运行
3. 双击 `start-server.bat`
4. 输入 `1`
5. 等桥接层启动
6. 打开 `http://127.0.0.1:8765/healthz`
7. 如果你想再多确认一步，再打开 `http://127.0.0.1:8765/health`

### 什么算第一步成功

如果：

- `/healthz` 能正常打开

那说明桥接层已经启动了。

如果：

- `/health` 也能正常返回内容

那说明桥接层这边已经能连到 `Intiface` 服务。

但这还不等于你的设备一定已经被识别或一定已经能控制。  
设备有没有真的被识别，仍然更建议以 `Intiface Central` 里实际显示的结果为准。

## 如果你想试 `custom`

这条路更适合下面这种情况：

- 你的设备不能被 `Intiface` 识别
- 官方 App 能控制
- 你的电脑本身有可用蓝牙
- 你已经知道自己的设备和当前项目已知路线比较接近，或者家机判断值得先试

如果你只是知道“官方 App 能控制”，还不能直接把它理解成“默认 `custom` 大概率就能用”。

### 你怎么做

1. 双击 `start-server.bat`
2. 输入 `2`
3. 在提示里输入你的设备名称关键词

这里的“关键词”通常就是：

- 你设备名称里最好认的一部分
- 不需要完整名称
- 也不需要蓝牙地址

例如你的设备名如果很长，就输入最容易识别的那一小段。

### 什么算第一步成功

桥接层启动后，打开：

- `http://127.0.0.1:8765/healthz`

如果它能正常打开：

- 说明桥接层已经按 `custom` 模式启动了

但这还不代表你的设备一定已经被支持或一定已经能连上。

## 如果你想再多确认一步

你还可以打开：

- `http://127.0.0.1:8765/docs`

这里会看到接口页面。

如果你和家机已经能发 HTTP 请求，后面更适合按顺序继续尝试：

- `connect`
- `set-strength`
- `stop`

如果你自己不想看接口细节，也可以把这份文档和下面这份一起交给家机看：

- [api-usage-for-ai.md](ai/api-usage-for-ai.md)

## 遇到这几种情况怎么办

### 1. 选了 `Q` 之后窗口直接消失

这通常是正常退出，不是报错。

### 2. `Intiface` 路线起不来

先检查：

- `Intiface Central` 有没有先打开
- 设备有没有真的被它识别

如果还不行，可以先看：

- [faq.md](faq.md)

### 3. `custom` 路线起不来

先检查：

- 这台 Windows 电脑是不是本身有蓝牙，或者已经插了蓝牙适配器
- 你的设备是不是能被官方 App 正常控制
- 你输入的设备名称关键词是不是太短或太模糊

如果你不确定设备到底在不在支持范围内，可以回去先看：

- [device-support-simple.md](device-support-simple.md)

### 4. 你想继续深一点判断

如果你已经试过，但还是不确定下一步怎么走，可以把下面这些交给家机看：

- [project-architecture-for-ai.md](ai/project-architecture-for-ai.md)
- [device-support-for-ai.md](ai/device-support-for-ai.md)
- [api-usage-for-ai.md](ai/api-usage-for-ai.md)

## 最后提醒

- `custom` 是兼容尝试，不等于一定支持
- `custom` 更适合当前项目已经掌握、或者和已知路线很接近的设备
- 先别把“官方 App 能控制”直接理解成“默认 `custom` 一定能用”
- 不需要一开始就碰高级配置
- 先把桥接层跑起来，再决定要不要继续深挖
